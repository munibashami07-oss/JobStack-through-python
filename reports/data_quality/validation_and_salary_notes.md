# Validation and salary notes

Hand-written companion to `data_quality_report.md`. That report is generated by
`python -m src.validation.quality_report` and is overwritten on every run, so these
notes live in their own file.

## 1. Rejected records

| source | validated (unique) records | rejected |
|---|---|---|
| remotive | 15 | 0 |
| arbeitnow | 2,598 | 0 |
| kaggle_pk | 5,398 | 0 |
| **total** | **8,011** | **0** |

Rules applied by `src/validation/models.py` (`JobPosting`):

- `posting_id`, `source`, `title` and `description` are required.
- `title` and `description` must not be blank after trimming.
- `salary_min` and `salary_max` must be numbers and must not be negative.
- `salary_min` must not be greater than `salary_max`.
- `posted_at` must be a valid date and must not be in the future.
- `source`, `work_mode` and `language` must be one of the allowed values.

Zero rejections means the real data passed these rules. The source adapters also clean the
data before validation (for example removing the "Jobs in Pakistan" suffix and moving the
location "Remote" into `work_mode`), which prevents some problems from reaching the
validator. Because the real data never triggered a rejection, the rejection path is
verified with deliberately broken records in `tests/test_rejection.py`. Each rule above has
a test that checks the record is refused with a readable reason, that all problems are
reported, and that one bad record does not stop the rest of a batch.

## 2. Salary coverage

| source | rows | rows with any salary information | rows with numeric salary_min / salary_max |
|---|---|---|---|
| remotive | 15 | 8 (53.3%) | 0 |
| arbeitnow | 2,598 | 0 | 0 |
| kaggle_pk | 5,398 | 0 | 0 |
| **total** | **8,011** | **8 (0.1%)** | **0** |

- Only 8 of 8,011 rows (0.1%) have any salary information. All 8 come from Remotive and
  are stored only as free text in `salary_text`. No row has a numeric `salary_min`,
  `salary_max` or `currency`.
- Arbeitnow and the Kaggle CSV have no salary field at all.
- Missing salary is stored as null. It is never set to 0 and never estimated.
- The 8 Remotive rows are global remote jobs, not Pakistan jobs.
- Consequence for later stages: salary analysis (salary by role, city, experience or skill
  count) is not possible with this dataset. Person 4 should report salary coverage as
  above and leave salary charts out, or pick a source that has salary data.
